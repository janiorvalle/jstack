# Placeholder content

These rules apply when you need a logo, avatar, screenshot, app image, wallpaper, or person photo and nobody gave you a real one.

- No logo file? Make a simple mark, one shape or one letter in an SVG, sized to the app name the user gave you, in a font that fits the design.
  - The mark can be white, black, dark gray, or an accent color. Keep any wordmark text white, black, or dark gray.
  - Leave the text off when only the icon is needed.
  - Don't build logos by hand out of HTML or icon fonts. One SVG file, reused everywhere.
  - Use the same approach for every other logo too: company logos in testimonials, client logo grids, and so on.
- App screenshots, dashboard images, and anything that should look like a real product use a real screenshot from the project if one exists, otherwise a screenshot you generate with your harness's image generation. Don't use Unsplash or stock photos for these. The content doesn't have to match, it just has to look like a real app at a glance.
  - For full-width or near-full-width hero images, use the whole screenshot. Don't crop at large sizes.
  - For feature section screenshots, crop to one region of the interface at a fixed size, a sidebar plus a list, a single panel, a header. Keep the same few crops across the page instead of inventing a new one per section.
- Give placeholder people unisex names, so the name works with whatever placeholder photo ends up there.
